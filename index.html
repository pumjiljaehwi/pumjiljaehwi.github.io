n8n

요구사항 분석부터 리포팅까지, QA 사이클 자동화

슬랙봇을 호출하고 PRD와 Jira 링크만 넣으면, 요구사항 분석서 작성부터 체크리스트 생성, 테스트 리포트 발송, Jira 코멘트 등록까지 하나의 흐름으로 이어집니다. QA가 판단에 집중할 수 있도록 그 앞뒤의 반복 작업을 걷어냈습니다.

Claude Code · Playwright MCP

AI로 생성하는 테스트 자동화

Claude Code와 Playwright MCP로 핵심 기능 자동화 스크립트를 생성하고 실행합니다. 버그로 판단되는 결과는 Jira에 자동으로 이슈 레이징되도록 연결했습니다.

How I Work

업무 방식

01
무엇을 자동화하고 무엇을 사람이 할지 가르기

모든 걸 자동화하는 게 답은 아닙니다. 반복되는 요구사항 분석·리포팅·모니터링은 n8n과 AI로 흐르게 만들고, 판단과 탐색이 필요한 검증은 사람의 몫으로 남깁니다. 그 경계를 정하는 일에서 자동화가 시작된다고 봅니다.

02
흩어진 정책을 문서로, 문서는 낡지 않게

테스트 정책뿐 아니라 기능에 대한 상위 정책까지, 구두로 전달되거나 개인 노트에 흩어져 있던 것들을 문서로 모았습니다. 한 번 정리하고 끝이 아니라 업데이트 규칙을 정해, 문서가 늘 최신 상태를 유지하도록 관리 체계를 만들었습니다.

03
도메인이 바뀌어도 다시 빠르게 올라서기

담당 도메인이 바뀌고 모바일에서 웹으로 제품이 바뀌는 상황을 겪으며, 새 도메인을 Notion·Confluence로 정리해 빠르게 온보딩했습니다. 그 정리를 신규 입사자나 관련 업무자가 참고할 수 있도록 문서로 다듬었고, 이후로도 지속적으로 최신화하고 있습니다.

04
AI를 도구가 아니라 일하는 방식으로

AI를 한 번 써보는 데서 그치지 않고, 요구사항 분석부터 테스트 스크립트 생성까지 업무 흐름에 일관되게 녹였습니다. AI 기반 제품을 테스트하기 위한 정책을 PM과 함께 논의한 경험도 있습니다.

05
두 조직 사이에서 방향을 맞추기

기능 조직(QA팀)과 목표 조직(스쿼드) 양쪽에 속해 각 조직의 OKR과 KPI를 함께 달성하려 했습니다. 기능 조직에서는 QA 직무 레벨을 끌어올리는 일에, 목표 조직에서는 깊은 도메인 이해를 바탕으로 높은 테스트 커버리지를 확보하고 PRD 리뷰 같은 앞단에서 크리티컬한 이슈 리스크를 조율했습니다. 그 과정에서 기획·개발·디자인과 직접 소통하며 일정과 우선순위를 맞춰왔습니다.
